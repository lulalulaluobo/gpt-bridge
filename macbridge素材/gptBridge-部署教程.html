00
DOWNLOAD & INSTALL

从项目仓库下载安装

本教程以当前 macOS 界面为主；发布页同时提供 Windows 安装包。

打开 gpt-bridge 项目仓库 ↗，从右侧进入 Releases，或直接打开 发布页面 ↗。

在发布详情的 Assets 中选择匹配系统与架构的文件。截图中的 gpt-bridge-0.11-arm64.dmg 用于 Apple Silicon Mac，gpt-bridge-0.11-windows-x64-setup.exe 用于 Windows x64；不要把 Source code 压缩包当作安装包。

  1. macOS：下载 DMG，打开后将 gpt-bridge.app 拖入 Applications。
  2. 推出安装卷，再从 Applications 打开应用。发布包带有运行依赖，无需为基本连接另外安装 Node.js 或 Python。
  3. 升级用户先断开并退出旧应用；避免同时运行旧 MacBridge 和新 gpt-bridge。
  4. 如遇系统拦截，在确认安装包来源后按项目说明通过“隐私与安全性 → 仍要打开”处理。

如果 macOS 阻止首次打开，只在确认安装包来自官方 Releases 后，前往“系统设置 → 隐私与安全性”允许打开。本项目当前发行包尚未完成 Apple 公证。

准备项检查内容
可持续联网的 Mac安装完成，运行时保持开机；睡眠、断网或关机会影响远程调用。
ChatGPT 工作区当前账号允许添加并使用自定义 MCP 插件。
OpenAI Platform 组织能创建 Tunnel，并将目标 ChatGPT 工作区关联进去。
授权目录先确定主工作区及需要访问的资料目录；先用测试文件验收。

本教程用 gpt-bridge、gptBridgeWorkspace 和 gbm 作为名称示例，分别代表应用、目录工作区和网页插件；实际使用时按自己的设置选择名称。

01
OPENAI PLATFORM

创建 Tunnel，准备运行 Key

先获取 Tunnel ID，再创建本机运行所需的 Runtime API key。

打开 OpenAI Platform · Tunnels ↗，确认组织正确，点击右上角 Create tunnel。

填写 Name 和 Description，选择拥有该隧道的 Organizations，并关联将安装插件的 ChatGPT workspaces。创建与编辑需要 Tunnels Read + Manage；运行及选择隧道需要 Read + Use。[1]

点击 Create 后复制完整 Tunnel ID（以 tunnel_ 开头），供本机应用和 ChatGPT 插件共用。

创建 Runtime API key

进入同一组织下的 API keys ↗，点击 Create new secret key。选择受限权限，按官方运行客户端说明授予 Tunnels Read + Use，对应身份本身也必须具备这些权限。[3]

创建新 Key 时选择受限权限，只启用 Tunnels 的 Read 与 Use。生成后立即把 Runtime API key 填入本机应用；完整密钥不要发到聊天、截图或仓库。

两个值分别填写

Tunnel ID 标识通路，Runtime API key 用于本机客户端鉴权。完整运行 Key 只填入本机配置，不粘贴进聊天或教程截图；不要用 Admin key 替代。

已拿到自己的 Tunnel ID 与运行 Key，并关联目标 ChatGPT 工作区。
02
GPT BRIDGE APP

配置工作区、权限和连接

按当前界面进入“连接与设置”，填写两个字段，再应用并连接。

  1. 打开 连接与设置。新部署点击 添加连接；只有已有脚本部署才使用“导入已有部署”。
  2. 填写名称、Tunnel ID 与 Runtime API key，点击 应用并连接。
  3. 返回工作区，核对主目录及只读 / 读写权限；目录配置变更后点击 应用修改。仅“保存”不会立即重启连接应用新权限。

把 Obsidian 加入共用目录

进入 共用目录 → 添加文件夹，选择自己的 Vault，逐项选择只读或读写。共用目录适用于所有工作区；只读测试不要求打开写权限。

读取本地 Skill：方法库

进入 方法库 → 添加目录，选择本地 Skills 文件夹，然后搜索并读取方法正文。方法库只读文档，不要求把 Skills 再加入普通共用目录，也不会自动执行文档中的脚本。

若要用 obsidian_query 查询笔记，当前项目文档要求 Vault 已授权、Obsidian 已打开且官方 CLI 已启用。该工具只读；需要写入时使用有写权限的文件工具并回读核对。

命令开关与目录权限分开管理

工作区的“允许执行命令”可单独设置。目录文件权限不是系统级命令沙箱；连接与文件读取测试可先使用最小所需权限。

本机已连接，主目录、共用目录和方法库均按实际需求配置。
03
CHATGPT PLUGINS

创建自定义 MCP 插件

在 ChatGPT 中选择隧道连接方式，连接自己部署的服务。

进入 插件页面 ↗，点击 添加 → 添加自定义 MCP 服务器。

  1. 填写名称与说明，例如 gbm 或自己易识别的名称。
  2. 连接方式选择 隧道，选与本机相同的 Tunnel；不要填写本机 localhost 地址。
  3. 本项目的 MCP 服务没有配置 OAuth，选择 无需身份验证。其他配置了 OAuth 的服务应按自身认证要求填写。
  4. 阅读页面提示，勾选确认后创建插件；进入连接流程时核对名称并确认连接。

“无需身份验证”描述 MCP 服务这一层。本机仍使用 Runtime key，隧道仍受组织、工作区及权限控制。[1]

完成创建并进入自己的插件详情；填完表单还不算完成。
04
CONNECT & INSPECT

检查插件状态和工具

本教程示例插件名为 gbm；实际部署时可自定名称。

打开应用工具详情，核对 method_library 和 obsidian_query 等所需工具是否可见。工具出现在列表中仍不代表真实读取已通过。

服务更新或增加工具后，在插件管理中 刷新工具，确认需要的工具可用，再开新对话。刷新网页不等于刷新工具定义。[2]

插件已连接，所需工具出现在列表中，并能在新对话中选中。
05
VERIFY WITH REAL FILES

用真实文件完成验收

让模型读到它事先不知道的内容，比让它重复一句口令更有说服力。

可选：验收 Obsidian 查询。在 ChatGPT 中选中 gbm 插件，要求它用 obsidian_query 查找一篇确定的笔记，再与 Obsidian 本机原文核对。确认看到了实际工具调用和返回结果；工具列表中出现名称本身不代表读取已通过。

以下是验收步骤，不是已经执行过的测试报告

建议在独立工作文件夹内操作。先读，后写；不以“我已经完成”的文字回复代替工具结果，也不把全部测试一次性堆给模型。

凭据一：工具实际返回

检查工具名、路径、错误或结果；不要只看回复里是否写了“成功”。

凭据二：本地可独立核对

在 Finder / 文本编辑器里检查文件。网页端说对了，本地也对得上，才算闭环。

本步完成标准：真实读取通过；在账户支持且你需要写入时，新文件写入、重读和本机核对也通过。
06
LIFECYCLE CHECK

检查后台运行与主动断开

窗口关了、应用退出了、连接断了，是三件不同的事。

当前“连接与设置”中提供 “登录 Mac 时启动” 与 “启动应用后自动连接”；连接诊断位于同一设置页。项目文档说明关闭设置窗口后菜单栏与连接继续运行，主动断开不会立即自动重连；请按下面步骤实测。

建议测试你的操作判断依据
关闭窗口关闭应用窗口，不退出应用，再读取一份新的测试文件。按截图声明应仍可调用；以实际返回为准。
主动断开在 gpt-bridge 点击“断开”，再请求读取新文件，只尝试一次。这次调用应返回不可用 / 错误或超时，而不是把旧内容当新结果；失败后停止。
重新连接回应用重新连接，再读取另一份新文件。应恢复真实读取；不要用前一次缓存文字充当证据。
自动启动 / 连接基础测试通过后，再按需开启两项开关，并在方便时重登录测试。重登录后重新发起实际调用核对；不要仅凭开关已勾选判断。
异常时先断开，不要先扩大权限

发现了不符合预期的命令或写入行为，先在本机断开连接，再检查工具调用记录、文件变更与诊断信息。密钥可能泄露时，应在 Platform 撤销或轮换；断开连接不等于撤销密钥。

07
TROUBLESHOOTING

排错，先定位是哪一层

不要把所有失败都归到 ChatGPT，也不要第一步就重装整个环境。

现象优先检查下一步
ChatGPT 找不到隧道关联的 ChatGPT 工作区、创建插件者的 Read + Use 权限。在 Platform 核对关联与权限；粘贴 ID 不能绕过工作区授权。[1]
无法发现 OAuth 设置MCP 服务实际有没有 OAuth；表单是否仍在使用旧选择。本教程无 OAuth 的测试配置才选“无需身份验证”；仍失败就核对本地服务和认证，不盲目反复创建。
显示已连接，但调用超时Mac 是否开机联网、应用 / 隧道客户端是否仍运行、是否主动断开。先恢复本机连接，再用新测试文件验证；保留真实错误与时间。
Path not allowed目标是否位于当前工作区主目录或已授权共用目录，读写权限是否匹配。把需要处理的文件副本放进工作文件夹，使用绝对路径；不要直接把授权目录改成整个磁盘。
工具不存在 / 参数不匹配服务端工具是否更新、插件是否仍保留旧定义。更新 / 重启服务 → 刷新工具 → 核对列表 → 新对话重测。[2]
运行密钥报鉴权错误密钥是否有效、所属组织是否正确、对应身份是否有运行权限。在 Platform 检查 Runtime key；不要将 Admin key 填入应用来“试试看”。[3]
只有回答，没有实际工具结果是否在对话里选中了正确插件，模型是否真正发起调用。缩小为一次 read_file 测试；要求报告实际错误，不接受复述输入作为通过依据。

三条不能省略的权限边界

  1. 目录边界：文件工具限定的工作目录不是命令执行沙箱。不要用终端工具绕过一次已经明确拒绝的文件访问。
  2. 数据边界：本地文件留在 Mac 上，不代表读取后的内容也只留在本地。仅让工具返回完成任务必要的数据，避免密钥、证件与无关私人资料。[4]
  3. 操作边界：删除、覆盖、批量移动、执行脚本前先看路径、影响范围和回退办法；提示词约束不能替代服务端权限与操作审查。

向他人提交诊断信息前，遮盖 Runtime key、组织 / 工作区与应用标识、私密路径和文件内容。公开版本未附作者账号截图与本机录屏，以免泄露私人侧栏、账户名称和本机路径；操作选项请在自己的账户中核对。
