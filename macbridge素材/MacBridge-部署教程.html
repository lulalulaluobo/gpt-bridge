00
BEFORE YOU START

开始前，先看这里

本教程走 MacBridge 桌面应用路线，不是从源码构建教程。

前提：你已经获得并能打开 MacBridge.app

本次素材只有操作截图，没有安装包、公开下载地址或构建说明。还没拿到应用时，先向提供方获取匹配版本；本页从应用可启动之后开始。截图显示“个人预览版 · 0.1.0”。

MacBridge 在本教程中负责连接你的 Mac 与 ChatGPT。网页端发起工具请求，本机执行并返回结果。OpenAI Secure MCP Tunnel 使用出站连接，让私有 MCP 服务接入支持它的 OpenAI 产品，不必把本地服务直接暴露成公网入口。[1]

ChatGPT发起工具调用
→
OpenAI 隧道转交 MCP 请求
→
MacBridge本机服务执行
→
工作文件夹读取 / 写入结果
准备项检查什么
一台可持续联网的 Mac能启动 MacBridge，运行期间保持开机；不要把睡眠或关机后的可用性当作默认条件。
ChatGPT 网页端当前账号和工作区允许添加、使用自定义 MCP 服务器。入口与能力以实际账号为准，不由这份教程保证。[2]
OpenAI Platform 组织能进入 Tunnels。创建 / 编辑需要 Tunnels Read + Manage；运行客户端、选择隧道需要 Read + Use。[1]
Runtime API key给本机隧道客户端使用的运行密钥。不是 Tunnel ID，也不要用 Admin API key 代替。[3]
独立工作文件夹先只放测试文件、项目副本，不要直接授权整个个人目录。

名称说明：素材里的早期插件叫 MacBridge-Test，后续页面叫 MacBridge。本文统一用 MacBridge 指代你要连接的插件；操作时以自己创建的名称为准。

01
OPENAI PLATFORM

创建 OpenAI 隧道

先得到 Tunnel ID，再准备给本机使用的 Runtime API key。

打开 OpenAI Platform · Tunnels ↗，确认当前组织正确，点击 Create tunnel。

填写名称，并关联正确的工作区

字段怎么填
Name便于识别的名称，例如 macbridge-personal-test。
Description说明用途，例如“个人 MacBridge 文件读写测试”。
Organizations选择拥有或管理这条隧道的 Platform 组织。
ChatGPT workspaces选择你准备安装插件的 ChatGPT 工作区。只关联组织，并不等于目标工作区能看到它。[1]

点击 Create 后，记录系统生成的完整 tunnel_id。它通常带有 tunnel_ 前缀；始终复制实际返回值，不要照抄别人的截图。后面 MacBridge 与 ChatGPT 要使用同一条隧道。

补充步骤：准备 Runtime API key

进入同一组织下的 Runtime API keys 页面 ↗，创建一把 Restricted（受限）运行密钥，仅选择 Tunnels Read + Use；对应身份本身也必须具备这些权限。这一步的界面没有出现在素材中，入口与权限说明参考官方客户端文档。[3]

两个值，分别使用

Tunnel ID 用来选择哪条隧道；Runtime API key 用来让本机客户端向 OpenAI 验证运行身份。不要把密钥贴进 ChatGPT 对话、教程截图或排错帖子。

本步完成标准：你已经拿到自己的 Tunnel ID 和 Runtime API key，并关联了将要使用插件的工作区。
02
MACBRIDGE APP

在 Mac 上保存并连接

新部署添加连接；已有脚本部署才考虑导入。

  1. 打开 MacBridge，新用户点击左下角 “添加连接”。
  2. 填写一个便于识别的名称，例如 MacBridge。
  3. 将上一步的 Tunnel ID 和 Runtime API key 分别填入对应字段。
  4. 点击工作文件夹旁的 “选择…”，选一个独立目录，例如 /Users/你的用户名/MacBridgeWorkspace。
  5. 点击 “保存并连接”。不要只点“保存”就去网页端测试；接下来还要确认服务实际可调用。
首次配置

新连接必须填运行密钥

素材的字段提示为“新连接必填；已保存时留空保留”。界面还说明密钥保存在本机钥匙串中；这是应用界面声明，不等于本教程完成了实现审计。

已有部署

导入不是新用户必选步骤

截图处于“已有脚本服务运行中 / 已导入”状态。按该版本提示，连接时会先停止旧服务并保留旧文件；切换前先核对状态，不要手动删除原部署。

工作文件夹限制 ≠ 整台 Mac 的安全沙箱

应用截图明确提醒：文件工具默认限制在所选目录，但命令仍以当前 Mac 用户权限运行。因此先验证文件工具；写入、删除、执行命令等高风险操作保留审查，不要仅凭“设置了工作目录”就全部放行。

旧部署切换补充：官方 tunnel-client 对同一 Tunnel ID 下的 stdio 部署不支持多个活跃客户端同时运行。使用这一模式时，确认旧实例停止后再启动替代实例。[5]

本步完成标准：连接资料已经保存，并已发起连接；没有未处理的报错。本地应用和隧道客户端应保持运行，再继续添加插件。
03
CHATGPT PLUGINS

添加自定义 MCP 插件

这里选择“隧道”，不是填写你 Mac 的 localhost 地址。

在 ChatGPT 网页端进入 插件页面 ↗，点击右上角 “添加” → “添加自定义 MCP 服务器”。当前官方插件连接文档也使用这条路径；账号和工作区策略仍然适用。[2]

字段本教程的填写方式
名称MacBridge 或自己易识别的名称。截图中的 MacBridge-Test 只是示例名称。
连接选择 隧道 / Tunnel。
隧道选择从列表选你的隧道，或粘贴实际 Tunnel ID；与 MacBridge 中填写的值保持一致。
身份验证本素材的个人测试服务采用 无需身份验证。仅当你连接的 MCP 服务本身确实没有配置 OAuth 时使用这一选项。
风险提示阅读说明、核对目标服务，确认理解风险后再创建为插件。不要连接来历不明的服务。
最容易卡住的地方：不要照抄截图里的 OAuth

早期截图先选了 OAuth，后面切换为“无需身份验证”，但底部仍显示“无法发现 OAuth 设置”。这张图只证明当时选项变了，不能证明错误已解决或创建已成功。

展开两张认证配置截图：识别前后状态，而不是照抄报错

确认服务为无 OAuth 的个人测试配置后，再选“无需身份验证”。若仍报 OAuth 错误，可取消并重新打开创建窗口，重新选择隧道和认证方式，再试一次；仍失败就检查本机服务、隧道状态和实际认证配置。需要 OAuth 的其他服务不能靠切成无认证来修好。

“无需身份验证”仅描述 MCP 服务这一层。本机运行客户端仍使用 Runtime key，隧道仍有组织 / 工作区关联与权限控制。它也不代表读取的内容不会进入 ChatGPT；工具返回的数据正是模型处理任务所需的上下文。[1][4]

本步完成标准：成功创建自己的插件，进入连接流程；不是只看到填写完毕的表单或仍带错误提示的截图。
04
CONNECT & INSPECT

连接插件，并检查工具

先确认连的是自己的应用，再确认网页端认识这些工具。

在连接确认页阅读权限、数据与风险说明，确认名称无误后点击 “连接 MacBridge”（示例截图中的按钮是“连接 MacBridge-Test”）。

回到插件详情，查看是否出现 “已连接”。点击 “在聊天中试用”，或在新对话输入框中用 @ 选择插件。[2]

检查工具，不要只看绿色圆点

打开应用的工具详情，确认出现你准备使用的工具。素材中可以看到 create_directory、edit_block 等；文件验证还需要实际公开 read_file 和 write_file。如果列表没有对应工具，先处理版本或工具刷新问题，不要直接让模型凭空调用。

服务端工具名称、参数或描述改变后，先部署 / 重启本地服务，再进入插件管理页面 “刷新工具”，确认列表更新，最后开一个新对话重测。只刷新网页，不一定等于刷新服务的工具定义。[2]

截图中的“全部允许”不是部署要求

读文件与写文件、执行命令的风险不同。根据当前账号提供的权限选项按需设置；对修改、删除和命令执行保留必要确认，不必为了连通测试一律放行。

本步完成标准：插件已连接，工具列表与准备测试的功能匹配，并能在对话中选择正确的插件。
05
VERIFY WITH REAL FILES

用真实文件完成验收

让模型读到它事先不知道的内容，比让它重复一句口令更有说服力。

以下是验收步骤，不是已经执行过的测试报告

建议在独立工作文件夹内操作。先读，后写；不以“我已经完成”的文字回复代替工具结果，也不把全部测试一次性堆给模型。

TEST A / READ

先生成一份模型不知道内容的测试文件

在 Mac 的终端执行下面这段命令。它会创建测试子目录和一个独立随机文件，只输出文件路径；随机内容不需要复制进对话。若你在应用里选择了其他工作目录，先修改第一行。

在你的 Mac 终端运行；仅创建测试目录与新文件
WORKSPACE="$HOME/MacBridgeWorkspace"
mkdir -p "$WORKSPACE/fixtures" "$WORKSPACE/outputs"
TEST_FILE="$WORKSPACE/fixtures/macbridge-read-$(uuidgen).txt"
(umask 077; set -C; printf 'macbridge-read-ok:%s\n' "$(uuidgen)" > "$TEST_FILE") &&
printf '让 ChatGPT 读取这个完整路径：\n%s\n' "$TEST_FILE"

不使用终端也可以：在授权工作文件夹中用文本编辑器保存一个纯文本文件，写入一串新的随机文字，只把文件的绝对路径交给 ChatGPT。

返回实际工具结果。不要执行命令，不修改文件；
不要根据上下文猜测内容。调用失败就报告实际错误。

通过标准：出现实际 read_file 调用，返回文本与本机文件内容完全一致。打开本机文件自行对照；没有实际工具结果就不算通过。

TEST B / WRITE & READ BACK

只创建一个新文件，写完再重读

确认当前插件具备写入工具后再做这一项。将提示词里的用户名改成自己的；也可以换成一个新的测试文件名。目标已存在就停止，不覆盖它。

先替换“你的用户名”，再发送给 ChatGPT
仅使用 MacBridge。
目标文件：/Users/你的用户名/MacBridgeWorkspace/outputs/macbridge-write-check.txt
内容：macbridge-write-ok

先用 read_file 检查目标；只有明确“文件不存在”才创建。
文件已存在、无权限或其他错误，都停止，不覆盖。
使用 write_file，mode 为 rewrite，内容不加换行。
遵循平台要求的确认流程，完成后用 read_file 重读。
报告写入与重读的实际工具结果。

通过标准：写入工具有实际返回；随后 read_file 重读得到 macbridge-write-ok；本机打开目标文件也一致。测试完成前，先不要用正式资料试批量修改。

凭据一：工具实际返回

检查工具名、路径、错误或结果；不要只看回复里是否写了“成功”。

凭据二：本地可独立核对

在 Finder / 文本编辑器里检查文件。网页端说对了，本地也对得上，才算闭环。

本步完成标准：真实读取通过；在账户支持且你需要写入时，新文件写入、重读和本机核对也通过。
06
LIFECYCLE CHECK

检查后台运行与主动断开

窗口关了、应用退出了、连接断了，是三件不同的事。

MacBridge 截图的“后台与诊断”区域提供 “登录 Mac 时启动”、“启动应用后自动连接” 和 “导出诊断状态…”。界面说明关闭窗口后菜单栏与连接继续运行，主动断开后不会自动重连；这些行为仍应在你使用的版本上实测。

建议测试你的操作判断依据
关闭窗口关闭应用窗口，不退出应用，再读取一份新的测试文件。按截图声明应仍可调用；以实际返回为准。
主动断开在 MacBridge 点击“断开”，再请求读取新文件，只尝试一次。这次调用应返回不可用 / 错误或超时，而不是把旧内容当新结果；失败后停止。
重新连接回应用重新连接，再读取另一份新文件。应恢复真实读取；不要用前一次缓存文字充当证据。
自动启动 / 连接基础测试通过后，再按需开启两项开关，并在方便时重登录测试。重登录后重新发起实际调用核对；不要仅凭开关已勾选判断。
异常时先断开，不要先扩大权限

发现了不符合预期的命令或写入行为，先在本机断开连接，再检查工具调用记录、文件变更与诊断信息。密钥可能泄露时，应在 Platform 撤销或轮换；断开连接不等于撤销密钥。

07
TROUBLESHOOTING

排错，先定位是哪一层

不要把所有失败都归到 ChatGPT，也不要第一步就重装整个环境。

现象优先检查下一步
ChatGPT 找不到隧道关联的 ChatGPT 工作区、创建插件者的 Read + Use 权限。在 Platform 核对关联与权限；粘贴 ID 不能绕过工作区授权。[1]
无法发现 OAuth 设置MCP 服务实际有没有 OAuth；表单是否仍在使用旧选择。本教程无 OAuth 的测试配置才选“无需身份验证”；仍失败就核对本地服务和认证，不盲目反复创建。
显示已连接，但调用超时Mac 是否开机联网、应用 / 隧道客户端是否仍运行、是否主动断开。先恢复本机连接，再用新测试文件验证；保留真实错误与时间。
Path not allowed文件是否在 MacBridge 选择的工作文件夹之内。把需要处理的文件副本放进工作文件夹，使用绝对路径；不要直接把授权目录改成整个磁盘。
工具不存在 / 参数不匹配服务端工具是否更新、插件是否仍保留旧定义。更新 / 重启服务 → 刷新工具 → 核对列表 → 新对话重测。[2]
运行密钥报鉴权错误密钥是否有效、所属组织是否正确、对应身份是否有运行权限。在 Platform 检查 Runtime key；不要将 Admin key 填入应用来“试试看”。[3]
只有回答，没有实际工具结果是否在对话里选中了正确插件，模型是否真正发起调用。缩小为一次 read_file 测试；要求报告实际错误，不接受复述输入作为通过依据。

三条不能省略的权限边界

  1. 目录边界：文件工具限定的工作目录不是命令执行沙箱。不要用终端工具绕过一次已经明确拒绝的文件访问。
  2. 数据边界：本地文件留在 Mac 上，不代表读取后的内容也只留在本地。仅让工具返回完成任务必要的数据，避免密钥、证件与无关私人资料。[4]
  3. 操作边界：删除、覆盖、批量移动、执行脚本前先看路径、影响范围和回退办法；提示词约束不能替代服务端权限与操作审查。

向他人提交诊断信息前，遮盖 Runtime key、组织 / 工作区与应用标识、私密路径和文件内容。本文图片使用脱敏副本；原始素材仍保留。
